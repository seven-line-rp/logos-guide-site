# ИИ-помощник LOGOS AI

**LOGOS AI** — искусственный интеллект сайта «Логос: Путеводитель». Разработчик — Лисовой Данила, студент 1-го курса группы П-1. В интерфейсе помощник выступает только под этим именем и не рассказывает, какая модель отвечает за него: правило закреплено в системном промпте `server/assistant-knowledge.mjs` и проверяется тестом `server/assistant-knowledge.test.mjs`.

Помощник открывается кнопкой «LOGOS AI» в шапке (на всю страницу, работает на любом экране) и плавающим окном в правом нижнем углу на компьютере. Простые вопросы — «где библиотека», «что умеет сайт», «построй маршрут от столовой до библиотеки» — он закрывает сам, без обращения к модели и без ключа (`src/assistant-intents.js`), а на просьбу о маршруте показывает анимированное построение и открывает страницу маршрута. По остальным вопросам он отвечает по каталогу помещений и возможностям сайта, но не получает расписание, контакты, стоимость обучения, список преподавателей или актуальные объявления и должен прямо говорить, если данных нет.

## Диалоги и команда «Туторил»

- Диалоги хранятся **только в браузере посетителя**: `logos-ai-chats` (список) и `logos-ai-active-chat` (текущий). Их можно переключать, переименовывать и удалять; сервер переписку не пишет. Пустые диалоги не сохраняются, в списке держится не более 25 последних.
- Команда **«Туторил»** в чате запускает интерактивное обучение по сайту: прожектор вокруг элемента, подсказка и кнопки «Далее» / «Понятно». Запрос к модели при этом не отправляется. Шаги — в `src/tutorial.js`, отрисовка — в `src/components/SiteTour.jsx`.

## Важно про ключ

Браузер **не обращается к модели напрямую**. Запрос проходит через сервер `/api/chat`, а ключ хранится только в серверном окружении: `LOGOS_AI_API_KEY` (старое имя `DEEPSEEK_API_KEY` продолжает читаться, чтобы не ломать существующие деплои). Не добавляйте ключ в React-код, `VITE_*`, публичный репозиторий или клиентский `.env` для сборки. Реальный `.env` уже исключён из Git.

Ключ выдаёт провайдер модели, к которому подключён проект; API тарифицируется по токенам, поэтому лимит запросов на сервере (12 в минуту с адреса) — не формальность. Тарифы провайдера меняются: проверяйте их перед запуском.

## Локальный запуск

1. Скопируйте `.env.example` в `.env` и укажите серверный ключ:

   ```dotenv
   LOGOS_AI_API_KEY=ваш_секретный_ключ
   PORT=3000
   ```

2. Для разработки запустите Vite. Встроенный сервер API читает `.env` и отвечает на `/api/chat`:

   ```bash
   npm ci
   npm run dev
   ```

3. Для проверки production-варианта:

   ```bash
   npm run build
   npm start
   ```

   Откройте адрес, указанный в терминале. `server.mjs` отдаёт сайт из `dist` и обслуживает API на том же origin. На сервере продакшена задайте `LOGOS_AI_API_KEY` как секрет переменной окружения; файл `.env` туда добавлять необязательно.

Если ключ не настроен, `/api/chat/status` вернёт `{"configured": false, "assistant": "LOGOS AI"}`, интерфейс покажет статус «ИИ ещё не подключён», а `/api/chat` ответит `503` без обращения к модели. Обучение «Туторил», список диалогов и сама переписка работают и без ключа — они живут в браузере.

## Размещение

`npm run preview` и обычная статическая публикация папки `dist` **не запускают серверный API**. Текущий общий хостинг с Apache/nginx, настроенный только на статику (см. [`reg-ru.md`](reg-ru.md)), продолжит отдавать сайт, но `/api/chat` там работать не будет. Для живого ИИ нужен Node.js-хостинг/VPS, запускающий `npm start`, либо отдельный серверless API с совместимым контрактом и проксированием `/api/chat` с того же домена.

### Сборка с внешним API (фронт на shared-хостинге, API — отдельно)

Когда фронт (`dist/`) лежит на статическом хостинге, а серверный `server.mjs` — где-то ещё (Railway, Render, VPS), задайте при сборке `VITE_ASSISTANT_API_URL` — полный URL внешнего API без завершающего слэша:

```bash
VITE_ASSISTANT_API_URL=https://logos-ai.up.railway.app npm run build
```

Готовый `dist/` будет ходить за `/api/chat` и `/api/chat/status` на этот URL. Если переменная не задана, фронт по-прежнему стучится на свой origin — для случая, когда фронт и сервер на одном домене.

Пример обратного прокси nginx для Node-сервера, работающего на том же VPS:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Если nginx — доверенный прокси и сам перезаписывает `X-Forwarded-For`, задайте серверу `TRUST_PROXY=true`, чтобы лимит запросов применялся к адресу посетителя, а не к адресу nginx. Не включайте этот параметр, если сервер доступен напрямую из интернета: клиент сможет подделывать этот заголовок.

## Ограничения и защита

- Сервер добавляет системные правила и фактический каталог помещений из `src/data.js`; клиент не может подменить системную инструкцию.
- API принимает только недлинную историю пользовательских/ассистентских сообщений, ограничивает размер запроса и делает не более 12 запросов в минуту с одного адреса.
- Ответы запрашиваются без потоковой передачи; запрос к модели ограничен 30 секундами.
- Не передавайте помощнику персональные или чувствительные данные. Для безопасности, расписания и актуальных административных вопросов обращайтесь к сотрудникам колледжа.
