# Выкладка на reg.ru

## Почему после F5 бывает 404

Сайт сделан как SPA: на сервере есть только один `index.html`, а адреса вроде
`/map` или `/route?from=118` обрабатывает React Router уже в браузере. Сервер
про `/map` ничего не знает и, если его не настроить, отдаёт 404. Внутри сайта
по ссылкам всё работает, а вот обновить страницу или открыть ссылку из
мессенджера не получится.

Чтобы это починить, сервер должен на любой неизвестный адрес отдавать
`index.html`. Для этого в проекте уже есть:

- `public/.htaccess` — правило для Apache, при сборке попадает в `dist`
- `public/404.html` — запасной вариант: если сервер всё-таки отдал 404, эта
  страница запоминает адрес и перекидывает на главную, а скрипт в `index.html`
  возвращает нужный адрес
- `deploy/nginx-spa.conf` — то же самое для nginx
- `deploy/static-host-sim.mjs` — маленький сервер, чтобы проверить это у себя

## Проверить у себя

```bash
npm run build
node deploy/static-host-sim.mjs dist
```

Открыть http://localhost:4173/map и нажать F5, страница должна остаться на карте.
У скрипта есть режимы через переменную `MODE`: `naive` (обычный хостинг, будет
404), `error404` (хостинг отдаёт наш 404.html) и `spa` (по умолчанию, так должно
быть после настройки). В PowerShell: `$env:MODE='naive'; node deploy/static-host-sim.mjs dist`.

## Залить на хостинг

```bash
npm ci
npm run build
```

Загрузить **содержимое** папки `dist` (не саму папку) в `public_html` домена.
Если заливаете по FTP, включите показ скрытых файлов, иначе `.htaccess` не
загрузится.

На обычном хостинге reg.ru (Apache) больше ничего делать не надо. Проверка:
открыть `logos-guide.ru/map`, нажать F5.

Проверка для поисковиков: в «Просмотреть код страницы» на `logos-guide.ru/map`
заголовок должен быть «Карта этажей | ЛОГОС:Путеводитель», а не заголовок главной.
Так Яндекс и превью ссылок видят каждую страницу (папка `_pages`, правило 0.5
в `.htaccess`).

Если всё равно 404:

1. В панели reg.ru (Хостинг → Сайты → домен) проверить, что сайт работает на
   Apache или nginx + Apache.
2. Проверить, что `.htaccess` лежит рядом с `index.html`.
3. В разделе «Страницы ошибок» поставить для 404 файл `/404.html`. Тогда хотя
   бы сработает запасной вариант.

## VPS или только nginx

Взять `deploy/nginx-spa.conf`, поменять `root` на путь к `dist`, добавить в
конфиг сайта и перезапустить:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

Главная строчка там `try_files $uri /_pages$uri.html /index.html;`: сначала файл,
потом копия страницы для поисковиков из `_pages`, потом `index.html`.

## Если проще написать в поддержку

> Домен logos-guide.ru — одностраничное приложение. Прошу для всех адресов, у
> которых нет реального файла, отдавать /index.html с кодом 200. Для Apache
> правило уже лежит в .htaccess в корне сайта, для nginx это
> `try_files $uri /index.html;`. И ещё прошу поставить
> `ErrorDocument 404 /404.html`.

## Проверка после выкладки

Открыть по прямой ссылке и обновить: `/map`, `/rooms`, `/route?from=118&to=214`,
`/games`, `/about`, `/docs`. Всё должно открываться. На несуществующий адрес
(например `/creators`) должна показаться наша страница «Такой страницы нет».

Без браузера:

```bash
curl -I https://logos-guide.ru/map                      # 200
curl -I https://logos-guide.ru/assets/no-such-file.js   # 404, так и должно быть
```
