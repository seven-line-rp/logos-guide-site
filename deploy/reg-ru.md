# Публикация на reg.ru: чтобы страницы открывались по прямой ссылке и после перезагрузки

Сайт — одностраничное приложение (React + React Router + Vite): на сервере лежит один
`index.html`, а адреса вроде `/map`, `/rooms`, `/route?from=118` разбирает приложение
в браузере. Поэтому сервер нужно попросить **на любой неизвестный адрес отдавать
`index.html`**. Без этого перезагрузка страницы (или переход по ссылке из мессенджера)
заканчивается ответом «404 — страница не найдена».

## Что уже сделано в репозитории

| Файл | Зачем |
| --- | --- |
| `public/.htaccess` | Правила для Apache: любой адрес → `index.html`. Попадает в `dist` при сборке. |
| `public/404.html` | Страховка: если сервер всё же отдал 404, страница запоминает адрес и возвращает посетителя на него. |
| `index.html` (скрипт `spa-fallback:restore`) | Подхватывает адрес из `404.html` до загрузки приложения. |
| `deploy/nginx-spa.conf` | Готовый блок для nginx (VPS или тариф только с nginx). |
| `deploy/static-host-sim.mjs` | Локальная имитация хостинга: можно воспроизвести ошибку и убедиться, что она ушла. |
| `src/spa-fallback.test.js` | Тесты возврата адреса (`npm test`). |

Проверка после сборки: `npm run build` — в `dist` должны лежать `.htaccess`, `404.html` и `index.html`.

## Шаг 0. Проверить локально, до загрузки на хостинг

```bash
npm run build
node deploy/static-host-sim.mjs dist          # MODE=spa — так работает хостинг после правки
```

Откройте `http://localhost:4173/map` и нажмите F5 — страница должна остаться на карте.
Режимы имитации (в PowerShell: `$env:MODE='naive'; node deploy/static-host-sim.mjs dist`):

| Режим | Что имитирует | Результат на `/map` |
| --- | --- | --- |
| `naive` | Обычный статик-хостинг без SPA-фолбэка | `404 Not Found` — та самая ошибка |
| `error404` | Хостинг отдаёт свою страницу `404.html` | Адрес восстанавливается клиентским скриптом |
| `spa` | `.htaccess` / `try_files` работают | `200`, страница открывается сразу |

## Шаг 1. Собрать и загрузить

```bash
npm ci
npm run build
```

Загрузите **содержимое папки `dist`** (не саму папку) в корень сайта на reg.ru —
обычно это `public_html` домена `logos-guide.ru`. Загружать нужно вместе со скрытыми
файлами: по FTP в клиенте включите показ файлов, начинающихся с точки, иначе
`.htaccess` не загрузится.

## Шаг 2. Общий хостинг reg.ru (Apache)

Ничего дополнительно настраивать не нужно, если `.htaccess` загрузился в корень сайта:
правила применяются автоматически. Проверьте: откройте `logos-guide.ru/map` и нажмите F5 —
страница должна остаться на карте.

Если перезагрузка всё ещё даёт 404:

1. В панели reg.ru → **Хостинг → Сайты** → ваш домен: убедитесь, что сайт работает
   на Apache (или nginx + Apache) и что `.htaccess` разрешён.
2. Проверьте, что `.htaccess` лежит **в том же каталоге, что и `index.html`**, и у него
   нет второго экземпляра в подкаталоге.
3. Включите в панели страницу ошибки: раздел **«Страницы ошибок»** / **«Error pages»**
   (или директива `ErrorDocument 404 /404.html`) — тогда даже без `mod_rewrite`
   посетитель вернётся на нужный адрес через `404.html`.

## Шаг 3. VPS или nginx-only тариф

Скопируйте `deploy/nginx-spa.conf`, поправьте `root` на путь к вашему `dist` и положите
фрагмент в конфиг сайта (например `/etc/nginx/sites-available/logos-guide.ru.conf`), затем:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

Ключевая строка — `try_files $uri $uri/ /index.html;`.

## Если настраивает поддержка reg.ru

Можно просто отправить в поддержку текст:

> Домен `logos-guide.ru` — статическое одностраничное приложение (SPA). Прошу для всех
> адресов, которым не соответствует реальный файл, отдавать `/index.html` с кодом 200:
> для Apache — разрешить `RewriteRule ^ index.html [L]` из `.htaccess` (файл уже загружен
> в корень сайта), для nginx — `location / { try_files $uri $uri/ /index.html; }`.
> Дополнительно прошу установить `error_page 404 /404.html;` (`ErrorDocument 404 /404.html`).

## Как проверить, что всё работает

Откройте по прямой ссылке и обновите страницу (F5) на каждом адресе:

- `/map`
- `/rooms`
- `/route?from=118&to=214`
- `/games`
- `/services`
- `/about`

Все они должны открывать свой раздел, а не «404». Адрес `/creators` в приложении не
существует — для него покажется собственная страница приложения «Маршрут не найден»
(это уже не ошибка сервера, а корректный ответ SPA).

Быстрая проверка без браузера:

```bash
curl -I https://logos-guide.ru/map          # ожидаем 200, а не 404
curl -I https://logos-guide.ru/rooms        # ожидаем 200
curl -I https://logos-guide.ru/assets/нет-такого-файла.js   # ожидаем 404 (статика не подменяется index.html)
```

Если `/map` отдаёт `404`, но в теле ответа виден `<!doctype html>` с нашим `404.html` —
значит, работает страховка: в браузере страница всё равно откроется, хотя статус лучше
починить правилами из шага 2 или 3.
